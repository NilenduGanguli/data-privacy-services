## Task 6 — The request guard (D4)

- `dps/layers/scanner/guard.py`: the plan's interface (`ALLOWED_METHODS`, `MIN_NEEDLE`, `HARDEN_JS`,
  `Decision`, `decide`, `BlockedRequest`, `ScanGuard.install/bind/arm/release/drain_counts/
  drain_blocked`, `blocked_total`, `websockets_closed`) and `HARDEN_JS` verbatim, made stricter
  where the plan left a way for data to leave the browser:
  - **`decide` gains two optional keywords** (additive, the plan's calls still work):
    `resource_type` and `method_override`. A method-override header (`X-HTTP-Method-Override`,
    `X-HTTP-Method`, `X-Method-Override`) or a `_method` query key makes a GET count as the other
    method (reason `method`): frameworks that honour them would treat the GET as a POST.
  - **New reason `filled_request`.** On a filled page every request that is not a passive resource
    (`PASSIVE_TYPES`: stylesheet, image, media, font, script, texttrack, manifest) is aborted — XHR,
    fetch, EventSource, beacons, `other` and an unknown (`None`) type. Why: the plan only looked for
    a fill value in the URL, so a GET fetch could carry one in a header, split over keys or encoded
    (base64, hashed) and still go out. Order of reasons on a filled page: `filled_navigation`,
    `filled_value`, `filled_request`. The plan test's `ok` case (`/static/app.css` on a filled page)
    now passes `resource_type="stylesheet"`.
  - **Fill values are checked on every page once armed**, not only on filled pages (the plan's
    `arm` docstring said so but its handler passed the needles only for filled pages). A draft the
    page kept in local storage can resurface on a later, unfilled page. Needles are the shown values
    of sensitive fields only (Task 11), so harmless URLs are not caught.
  - The value check normalises the URL as is and after each of up to four rounds of
    percent-decoding (the plan decoded once; `%2520` hid a value).
  - **Popups of a filled page are filled** (the route handler follows `page.opener()`), and are
    attributed to the opener's page number. `release(page)` never un-fills a page that is still
    open; a filled page is forgotten on its `close` event. Why: the plan's `_close` releases before
    closing, which left an open, filled page unguarded for that window, and `window.open` from a
    filled page opened an unguarded page.
  - **Fail closed:** if the decision cannot be computed the request is aborted, reason
    `guard_error`.
  - **Value-free counters.** `stored_method` records a non-standard method as `OTHER` (a page
    chooses a custom method's token, so it could carry a value — it would have reached
    `dps_scan_request.method` and a metric label). `stored_host` keeps an allowed host; any other
    host keeps only its last two labels when both are plain words (`*.` marks dropped labels),
    else `{host}` — a page can put data in a hostname (`<value>.tracker.example`). The plan stored
    the raw host. `BlockedRequest.url` is `field(repr=False)`; at most `MAX_BLOCKED_KEPT` (2000)
    blocked requests are kept in memory between drains (counters keep counting).
- `tests/scanner/test_guard.py`: the plan's 12 cases plus method override, multiple encodings,
  needles on unfilled pages, `filled_request` per type (6) and passive types (5), the value-free
  host/method, `BlockedRequest` repr, a static source check (one `route.continue_(`, the fixed
  method set, no click/press/dispatch), and a **browser proof against a local stdlib server that
  counts everything it receives** (positive control; from an unfilled page with the hardening off:
  fetch POST, method-override GET, XHR PUT, `sendBeacon`, a dedicated worker's POST, a WebSocket,
  another host, `requestSubmit` of a POST form — the server receives no non-GET, no upgrade, nothing
  for the other host; from a filled page: `submit()`/`requestSubmit()` counted as attempts, fetch,
  an image carrying a value, `window.open`, `location.href`, a navigation after `release` — none
  arrives, while a plain image and a later fresh page still load): 32 tests (plan: 12).
- `tests/scanner/conftest.py` is created here with `skip_or_fail` and `chromium` (plan: Task 7),
  because the guard's browser proof needs Chromium; Task 7 adds the demo-site and engine fixtures.
- Found while proving it (for Tasks 13–14): a navigation the guard aborts from a filled page
  commits Chromium's error page (`chrome-error://chromewebdata/`) in that tab, so the page's

  the plan's host-only callable; the scope change belongs to `CrawlScope` (Task 14).

## M4 lane verification round 2 — fix for N1 (popup realms no route sees)

- **N1 — POSTs from an `about:blank` popup's realm left the browser over HTTPS, uncounted**
  (`guard.py` `ISOLATE_JS`). A page that calls `window.open('')` can use the popup's realm at
  once, before Playwright has attached to the new target: nothing that realm sends is routed, and
  over HTTPS the scope proxy sees only the tunnel. `guard.close` stopped plain fetches, but a beacon
  and a `keepalive` POST outlive the close. The method rule therefore no longer rests on the route:
  - **Every realm, filled or not, locked or not:** `navigator.sendBeacon` always refuses (it is
    always a POST; returns `false`, counted `api_removed`/`beacon`); `fetch` always drops
    `keepalive` (counted `api_removed`/`keepalive`); `fetch` and `XMLHttpRequest` (`open` /
    `setRequestHeader` / `send` wrapped) refuse any method but GET/HEAD and any method override
    (`X-HTTP-Method-Override`-style header, `_method` query key) before a request exists. A refused
    fetch rejects with a `TypeError` and a refused XHR fires `error`/`loadend`, as a route abort
    would look to the page.
  - **Inert documents:** a document of a window born at `about:blank`, while it is `about:blank`,
    and every frame born inside one. In it, `fetch`, `XMLHttpRequest`, `EventSource`, `WebSocket`
    and `Worker` refuse *every* request (also GET: a popup the filled page opens after `arm` would
    otherwise carry the value out in a GET no route sees), and the document gets a meta
    `Content-Security-Policy` that loads nothing (`default-src 'none'`, `form-action 'none'`, …:
    images, scripts, styles, frames, pings, form POSTs). Found while building it: Chromium swaps the
    popup's first document for a second `about:blank` document in the **same** window (init scripts
    do not run again), and `document.open()` gives a document its opener's URL. So a document is
    marked inert (an own fixed property plus a realm-local set) when first seen at `about:blank`:
    on the return of the wrapped `window.open`, in the wrapped `Document.prototype.open/write/
    writeln`, or on a request; the mark survives `document.open()` (and so does the CSP, verified).
    The same-origin page a popup then loads reuses the window too, but is a new document, routed
    and not inert (the relay-popup tests still load their worker).
  - **Counting:** a popup can be scripted before Playwright has added the report binding to it, so
    `ISOLATE_JS` falls back to its opener's (or parent's) binding captured at birth (the row is then
    attributed to the opener's crawl page; through the popup's own binding it carries page `None`,
    as a popup is never bound to a crawl page). `_report` takes an optional fifth argument `why`
    (allow-list `REPORTED_REASONS = {api_removed, method}`, anything else counts `api_removed`);
    `REPORTED_KINDS` adds `fetch`, `xhr`, `eventsource`.
- **Deviation from the finding's wording** ("refuse … counted as `api_removed`"): a fetch/XHR refused
  *for its method* is counted with reason **`method`** and resource type `fetch`/`xhr` — the exact
  row the route wrote for it before (`test_crawler`, `test_no_submit` and the evidence pack keep
  their meaning: "a POST was refused because of its method"). Everything refused in an inert
  document, beacons and dropped `keepalive` flags are counted `api_removed`. Visible consequence: a
  page's own POST autosave, beacon and unload flush are now refused in JS rather than aborted by the
  route, so `closing` rows for POSTs became `method`/`api_removed` rows; the route's `closing` abort
  is still proven by a GET in the unload flush (`test_closing_a_page_through_the_guard_…`).
- Tests (`tests/scanner/test_popup_realms.py`, counting server over TLS, paths only):
  unguarded positive control (every load-time POST/PUT/DELETE/beacon/keepalive and the post-fill
  base64 GET fetch, GET XHR, image and POST XHR all arrive); **three full `ScanRunner` scans**
  (`new_scan_context`, hardening on) of the hostile page: 0 hostile requests received, the
  load-time and post-fill popups demonstrably opened (`/diag-*` images), page `done`, guard rows
  `POST beacon api_removed`, `GET fetch api_removed`, `GET xhr api_removed`, POST/PUT/DELETE
  refused; an inert-document test (subresources, a form POST, an `<a ping>`, a child frame's
  POST/GET, a socket, an EventSource, after `document.open()`, and a popup whose `opener` was
  nulled): unguarded all arrive, guarded none (the popup's own navigation is routed and allowed);
  a fakes-only test of the binding's kind/reason allow-list. On the HEAD code the scan test
  received `POST /hostile-beacon`, `POST /hostile-keepalive` and more, and the inert test leaked; a
  run with the CSP disabled leaked frame/ping/subresources, so the CSP is load-bearing.
  `test_guard.py` updated where the counted reason moved (see above).

  other copies on the page stayed readable (the disabled case regressed against `cbbac38`). The rule is now
  exact: a select draws its placeholder only when every string it draws is the label of a selected option
  **it lists** whose `value` is empty or blank (disabled or not: `<option value="" disabled selected>` is
  the classic placeholder) and each string is, whole, a short placeholder phrase
  (`classify.PLACEHOLDER_TEXT` / `is_placeholder_text`: a choosing verb, "please" before it, filler words
  such as "one", "an option", "from the list" and punctuation only; at most 40 characters, no digit, no
  "@"; or no letter or digit at all). A selected option with a value (disabled or not), text drawn beyond
  the listed options' labels, a customizable select and a listbox are never placeholders. The fill keeps
  its own broad prefix rule (`PLACEHOLDER_OPTION`, `personas_fill._usable`): it only decides which option
  the fill never picks. "Select your country" is now a value (swept; it takes an obfuscated capture):
  over-masking, accepted.
- **B3 — a listbox (pre-existing since M4).** A select with `size > 1` or `multiple` draws every option in
  its box; only selected options counted as shown, so a listbox classified ACCOUNT_NUMBER or PERSON_NAME
  with nothing selected was never boxed (the census classifies listbox options with the detectors only,
  which miss names and bare account numbers). `EXTRACT_JS` records `FieldFacts.listbox`
  (`el.multiple || el.size > 1`) and reads the label of **every** option of a listbox into
  `FieldFacts.drawn` (no 300 cap; the text budget still marks an oversized extraction `truncated`: no
  capture); `classify.shown_texts` returns all of them (facts built without `drawn` read every listed
  option), so `sensitive_prefilled` boxes a visible listbox whole whenever it is classified personal or a
  detector finds a value among its options, whatever is selected, and `shown_values` sweeps every option
  it lists. A listbox is also classified by what it shows (`classify_fields`), like a closed select.
