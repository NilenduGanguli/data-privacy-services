## Task 1 — Scanner extra, settings, posture, logging allow-list and metrics

- `dps/config.py`: `browser_metrics_port` is bounded `0..65535` instead of the plan's blanket
  "every other int `ge=1`". Why: `0` disables an ops server, exactly as M2's `worker_metrics_port`
  (contract §10 "`worker_metrics_port = 0` disables the worker's ops server"); tests of the
  browser-worker process need the same switch. The contract §10 row records the bounds.
- `dps/observability.py`: `job_id`, `pages`, `fields`, `phase`, `kind` and `elapsed_s` were already
  allow-listed by M1/M2; only `page_no depth decision resource_type blocked step persona` are new.
  The four `dps_scan_*` counters sit after the M2 counters (the plan says "next to
  `VERIFY_FAIL`"; placement only).
- `pyproject.toml`: `scanner = ["playwright==1.55.0", "pillow>=10.4"]` as planned; the contract's
  extras paragraph (§1) now lists `pillow>=10.4` for `scanner` too (it named Playwright only).
- `HANDOFF.md`: §4 gains an "M4 settings" table and §6 the two M4 posture checks. Why: contract
  §0.6 (HANDOFF changes in the same commit as any config change); the plan leaves docs to Task 25.
- `tests/test_config_m4.py`: the plan's 7 cases plus the M4-addition defaults, more bound cases
  (`browser_concurrency` 17, `scan_max_pages` 0, `scan_max_depth` -1, `scan_page_timeout_seconds`
  0, `scan_settle_ms` -1), a clean-prod case (no M4 posture message without the two settings) and
  the four metrics' label names: 14 tests (plan: 7).

## Task 4 — Scan specification, records and API models

- `dps/jobs_models.py`: `ScanScope`, `ScanAuth`, `FillSpec`, `CaptureSpec`, `ScanSpec`, `PATH_GLOB`,
  `SECRET_REF` and `JobSecret.scan_start_url` as planned (M2 shipped no placeholder `ScanSpec`).
  Every scan model is `extra="forbid"` **and** `hide_input_in_errors=True` (the nested M2 models
  through the scan-local `ScanConsistency`/`ScanPurpose` subclasses since the round-1 fix below) (the M2 convention: a
  start URL can carry personal data in its query, and pydantic's default error text would quote
  it). `FillSpec` checks the locale against `SUPPORTED_LOCALES` exactly (no `normalise_locale`
  mapping, so `fr_FR` is refused rather than silently becoming `en_US`). `ScanAuth` refuses both
  sources together and a `..` segment.
- `dps/layers/scanner/models.py`: the planned models, plus:
  - **Page data never reaches a `repr`.** Every facts field that can hold page data (labels,
    placeholders, titles, aria labels, name/id attributes, selectors, options, pre-filled values,
    rendered text, label hints, hrefs, form actions, frame paths, the page URL and title) is
    `Field(repr=False)`, and `ValidatedScan.__repr__` shows the origin and limits only (its
    `start_url` keeps the raw query). A traceback or a stray `repr()` therefore cannot carry page
    data. Test `test_page_facts_never_show_page_data_in_repr`.
  - `validate_scan` treats any `@` in the netloc as userinfo (the plan's `username is not None`
    misses `http://:pw@host/`), resolves and range-checks `max_depth` (0..5) and `max_pages`
    (1..`scan_max_pages`) for programmatically built specs too, and adds one code, `auth_invalid`
    (both storage-state sources, or a `..` ref, in a spec built around the model's validator).
    `hosts` is normalised (trimmed, lower-cased) into `ValidatedScan.hosts`.
  - `redact_scan_spec` also records the resolved `scope.max_pages` / `scope.max_depth` and two
    more value-free flags, `consistency.caller_key` / `caller_seed`, beside the planned
    `key_wrapped`. The run spec's `redact_spec` names these facts differently (`wrapped`, `kid`,
    `seed_fingerprint`); since the round-1 fix the scan also writes `wrapped`, the name M2's key
    custody reads.
  - `PersonaPreviewRequest` is `extra="forbid"` and checks its locale like `FillSpec`.
  - `ValidationMessage.text` is capped at 200 characters by the model (the plan's comment).
- Contract §3.3 (`JobSecret.scan_start_url`) and §9 (the M4 additions to `ScanSpec`, the accept-time
  codes incl. `auth_invalid`, and what the stored spec keeps) updated in this commit.
- **Not done here (Task 16):** `auth.storage_state_ref` is only validated for form. It must be
  resolved with the tenant-scoped resolver that SEC-2 introduces at integration
  (`DPS_SECRET_DIR/<tenant_id>/<ref>/`); nothing in M4 may resolve a ref in the global namespace.
- `tests/scanner/test_models.py`: the plan's 10 cases (parametrised codes extended with

## Task 5 — Scan store

- `dps/layers/scanner/store.py`: the planned interface and SQL. Decisions:
  - **jsonb as Python objects.** `dps/db.py` registers a `json.dumps`/`json.loads` codec for
    `json`/`jsonb` on every pool and on the migration connection, so (as the plan instructs in that
    case) jsonb parameters are passed as Python objects, not pre-encoded text; the `::jsonb` casts
    stay.
  - `add_request_counts` merges rows with the same key in Python before the multi-row upsert:
    PostgreSQL refuses `ON CONFLICT DO UPDATE` that touches one row twice in a statement
    ("cannot affect row a second time"), which a guard batch with two identical keys would hit.
  - `replace_fields` and `reset_scan` run in one transaction (a savepoint when the caller already
    holds one); `replace_fields` refuses a record whose `page_no` differs from the argument
    (`ValueError`, value-free).
  - `summary_counts` also returns `pages_discovered` and `pages_queued` (two `count(*)`s; the API's
    `ScanSummary` needs both); null aggregates come back as `{}`, every count as `int`.
  - `list_pages`/`list_events` clamp `limit` to 1..1000; `list_requests` orders by page (log-wide
    rows first), method, decision, reason, host.
  - `export_artefacts` takes the newest artefact per kind (`DISTINCT ON`) and returns only the kinds
    present.
  - `insert_evidence` refuses a pack whose `tenant_id`/`job_id` differ from the arguments and stores
    `pack.pack_version`. (M2's `save_evidence` also exists; Task 16 may use either.)
  - `browser_workers_online` passes the window as `float` (`make_interval(secs => …)` takes
    double precision).
- `tests/scanner/test_store.py`: the plan's 7 tests plus the schema-name check, keyset paging of
    pages, the RLS case on `get_page`, the in-batch duplicate key, `non_get_allowed` counting an
    allowed POST (and not a HEAD), and export artefacts + evidence insertion: 11 tests (plan: 7).

## Review round 1 fixes (G1: Tasks 1–5)

Review `M4-G1-review-r1.md`, blocking B1–B4, plus N1, N4 and N5 folded in. Every fix has a test that
fails on `9bfb88d`.

- **B1 — `redact_url` (`dps/layers/scanner/urls.py`).** A path segment is now `{id}` whenever it is
  value-like, whatever the classifier says: a run of 4+ digits, an alphanumeric run of 8+ characters
  with a digit, an `@`, an `=` or whitespace (or one of the id forms as before). The real M0
  `Detector(en_IN)` misses `SB-50100234567812`, `CUST0012345`, `acct-123456789012` and session
  tokens, so the structural rule is what catches them. Matrix parameters are redacted in every
  segment (`;jsessionid=<v>`; a key that is not a plain name `<k>`; a bare item `;<v>`). Query and
  matrix keys that are value-like are `<k>` as well. Tests run with a classifier that returns None
  and with the real detector (`test_redact_url_hides_account_numbers_customer_ids_and_session_tokens`,
  `test_redact_url_keeps_plain_route_segments`).
- **B2 — `template(url, classify)`.** **Signature change:** the classifier is now a required second
  argument. The template is value-free and is what gets persisted: path segments and hash-route
  segments follow `redact_url`'s rules (all-digit segments of any length are still `{id}`), matrix
  parameters are dropped, query keys and hash-route query keys are `<k>` when value-like. The raw
  dedupe key stays in worker memory (the crawl's seen-set of `canonical()` forms).
  `urls.template_is_value_free()` re-applies the structural rules, and `PageRecord.template` refuses
  anything that fails it (the error does not echo the value). The plan's Task 14 code is updated in
  the plan file to pass `self.classify_value`. A skipped other-host row now keys on
  `template(redact_origin(url), …)` (`host[:port]/`) instead of the raw `redact_origin` string,
  because the guard would refuse a port in the path part. Tests:
  `test_the_persisted_template_is_value_free`, `test_template_keeps_routes_and_shares_ids`,
  `test_a_page_record_refuses_a_raw_template`, `test_value_free_templates_pass_the_record_guard`.
- **B3 — scope path rail.** New `normalise_path(path)`: a backslash, `%2F` and `%5C` count as
  separators, `;` matrix parameters are stripped per segment (so `..;` is `..`), escapes of
  unreserved characters are decoded, dot segments are resolved, empty segments are dropped and a
  trailing `/` is kept. `path_matches` compares the globs (normalised too) against every reading of
  the path: that form, matrix parameters stripped before encoded separators are split (Tomcat), and
  encoded separators kept. New keyword arguments: `fold_case` and `every_reading`. New
  `path_verdict(path, allow, deny)`:
  - deny wins when any reading matches, ignoring case;
  - a non-empty allow list must match every reading, case-sensitively (fail closed both ways).

  `CrawlScope.navigation_verdict` and `validate_scan` (`start_url_denied`) both use it. Tests:
  `test_deny_cannot_be_bypassed_by_case_matrix_encoding_or_dots` (19 forms, including all the
  forms the review lists), `test_allow_is_matched_on_the_normalised_path_case_sensitively`,
  `test_normalise_path`, and five more `start_url_denied` cases in `test_validate_scan_codes`.
- **B4 — `extra="forbid"` at every level.** `dps/jobs_models.py` gains `ScanConsistency(ConsistencySpec)`
  and `ScanPurpose(Purpose)`, both with `extra="forbid"` and `hide_input_in_errors`.
  `ScanSpec.consistency` and `ScanSpec.purpose` use them, and `RunSpec` keeps the M2 models
  unchanged. Contract §9 names the subclasses and states that free-form dict values (`policy`,
  `auth.storage_state`, the consistency key material) are data, not model levels. Tests:
  `test_every_level_of_the_scan_spec_refuses_extra_keys` posts `submit` to every nested model and
  asserts there is no deeper model level; `test_the_run_spec_models_are_unchanged_by_the_scan_subclasses`.
- **N1 — request counts.** `RequestCount.count` is `Field(ge=1)`, and `030_scans.sql`
  `dps_scan_request.count` gains `CHECK (count >= 1)`. 030 is edited in place because it is unmerged
  and only on `m4`. Contract §2.4 is updated. Tests: `test_a_request_count_is_at_least_one` and two
  more cases in `test_check_constraints_refuse_unknown_codes`.
- **N4 — consistency flag names.** `redact_scan_spec` also writes `wrapped`, M2's name, beside
  `key_wrapped`. Contract §9 is updated.
- **N5 — authority differential.** `navigation_verdict` returns `other_origin` for any `@` or
  backslash in the netloc. urllib reads `http://evil.com\@demo-site:8410/` as demo-site, but a
  browser goes to evil.com. Tasks 6 and 14 must still navigate only to `canonical()` output.
- Not done (non-blocking, left for later tasks): N2 (flush idempotency, Task 14), N3 (tenant-bound
  composite FKs, platform-wide), N6 (IPv6 hosts fail closed), N7 (SEC-2 tenant-scoped
  `storage_state_ref`, Task 16), N8 (producer-side redaction of field and form facts, Tasks 8, 9
  and 14).

## Review round 2 fixes (G1: Tasks 1–5)

Review `M4-G1-review-r2.md`, blocking R2-B1, plus N-a and N-b folded in. Every fix has a test that
fails on `032b076`.

- **R2-B1 — short digit groups (`dps/layers/scanner/urls.py`).** The round-1 B1 rule list above missed
  numbers written as groups shorter than four digits. `_value_like` (used by path segments, query and
  matrix keys, and `template_is_value_free`, so by the `PageRecord.template` guard) now also treats
  decoded text as a value when it holds **6+ digits in all** (`501-002-345-678`, `501.002.345.678`,
  `501%2F002%2F345%2F678`, `+91-987-654-321`, `12-05-90`, `1a2b3c4d5e6f`) or a **date shape**
  (`1-5-90`: 1–2, 1–2 and 2–4 digit groups joined by `-`, `.`, `/` or a space). A number split over
  consecutive numeric path segments (`/acct/501/002/345/678`, `/dob/12/05/90`, `/acct/50-1/00-2/34-5`)
  is `{id}` in every one of them once the run holds 6+ digits; this applies to `redact_url` and
  `template`, and the guard refuses such a run as well as any all-digit path segment (which
  `template()` always makes `{id}`). Routes with fewer than 6 digits and no date shape stay readable
  (`/docs/v1.2.3/api/v2/faq/1/page/2/x86_64`). Over-redaction is the accepted failure mode: a
  version like `1.10.12` or a dated blog path becomes `{id}`. Tests (each with a None classifier and
  the real `Detector(en_IN)`): new cases in
  `test_redact_url_hides_account_numbers_customer_ids_and_session_tokens`,
  `test_the_persisted_template_is_value_free`, `test_a_page_record_refuses_a_raw_template` (the error
  echoes none of them), `test_redact_url_keeps_plain_route_segments` and
  `test_value_free_templates_pass_the_record_guard`.
- **N-a — deny edge forms.** `_readings` gains a fourth, lenient reading: every escape decoded (so
  `%3B` ends the name and a double-encoded `%252e` is read once more), the path ends at a NUL, and each
  name loses trailing dots and spaces (IIS/Windows). Deny still wins on any reading and allow must
  still match every reading, so the extra reading can only narrow scope. `/logout.`, `/logout%2e`,
  `/logout%20`, `/logout.%20.`, `/admin%00`, `/admin%00.html`, `/admin%3b/x`, `/admin%3Bx=1/users`,
  `/admin..;/` and `/admin%252e` are now `deny` (new cases in
  `test_deny_cannot_be_bypassed_by_case_matrix_encoding_or_dots`); `validate_scan` refuses
  `/admin.` and `/admin%00` as start URLs.
- **N-b — hash routes.** New `urls.route_path(url)` and `urls.url_path_verdict(url, allow, deny)`
  (additive; `path_verdict` is unchanged): a hash route (`#/x`, `#!/x`, the route query dropped) is a
  navigation too, so its path is checked against deny; allow still applies to the URL path only (a
  hash-routed SPA's routes need not be listed). `CrawlScope.navigation_verdict` and `validate_scan`
  (`start_url_denied`) use it, so Task 14 inherits it through `navigation_verdict`. Contract §9's
  `start_url_denied` text is updated. Test: `test_a_hash_route_is_a_navigation_the_deny_rail_covers`
  and two `start_url_denied` cases (`/#/admin`, `/app#!/Admin/x`).
- Not done (non-blocking, recorded): N-c (registered-host scope ignores port and scheme — Task 6/14
  should bind registered entries to `host[:port]`), N-d (a 422 echoes extra-key names in `loc`;
  platform-wide M0 behaviour, only the caller's own input), N-e (names in path segments are kept when
  the classifier has no NER — use the NER classifier in the worker when the `[ner]` extra is
  present, Task 14), N-f (`template_is_value_free` does not check the host part), and the round-1
  deferrals N2, N3, N6, N7, N8 as listed above.
