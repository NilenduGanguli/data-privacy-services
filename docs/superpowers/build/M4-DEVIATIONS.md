`docs/superpowers/plans/2026-10-11-m1-m5-contract.md` (incl. the 2026-10-12 lane-safe amendment).
One section per task: file, what changed, why. Contract names are preserved unless a section says

`/Users/neelu/document_intelligence/data-privacy-services` path and literal ports are superseded by

## Task 1 — Scanner extra, settings, posture, logging allow-list and metrics

- `dps/config.py`: `browser_metrics_port` is bounded `0..65535` instead of the plan's blanket
  "every other int `ge=1`". Why: `0` disables an ops server, exactly as M2's `worker_metrics_port`
  (contract §10 "`worker_metrics_port = 0` disables the worker's ops server"); tests of the
  browser-worker process need the same switch. The contract §10 row records the bounds.
- `dps/observability.py`: `job_id`, `pages`, `fields`, `phase`, `kind` and `elapsed_s` were already
  allow-listed by M1/M2; only `page_no depth decision resource_type blocked step persona` are new.
  The four `dps_scan_*` counters sit after the M2 counters (the plan says "next to
  `VERIFY_FAIL`"; placement only).
- `pyproject.toml`: `scanner = ["playwright==1.55.0", "pillow>=10.4"]` as planned; the contract's
  extras paragraph (§1) now lists `pillow>=10.4` for `scanner` too (it named Playwright only).
- `HANDOFF.md`: §4 gains an "M4 settings" table and §6 the two M4 posture checks. Why: contract
  §0.6 (HANDOFF changes in the same commit as any config change); the plan leaves docs to Task 25.
- `tests/test_config_m4.py`: the plan's 7 cases plus the M4-addition defaults, more bound cases
  (`browser_concurrency` 17, `scan_max_pages` 0, `scan_max_depth` -1, `scan_page_timeout_seconds`
  0, `scan_settle_ms` -1), a clean-prod case (no M4 posture message without the two settings) and
  the four metrics' label names: 14 tests (plan: 7).

## Task 2 — URL toolkit

- `dps/layers/scanner/urls.py`: the plan's code, plus:
  - `redact_url` also turns a query **key** the classifier recognises into `<k>`. The plan only
    checked the key's characters, so a key made of plain characters that is itself a value (an
    account number used as a key, `?50100234567812=on`) would have been stored verbatim. Test
    `test_redaction_never_keeps_a_query_key_that_is_itself_a_value`.
  - A malformed port (`http://h:99999/x`) never raises from `template`, `redact_url` or
    `redact_origin` (urllib's `.port` raises `ValueError` there; a guard that redacts arbitrary
    request URLs must not crash on one); `canonical` returns `None` and `Origin.of` raises
    `UrlError("url_invalid")` as before. Test `test_a_malformed_port_is_never_echoed_and_never_raises`.
  - `Origin.text()` (`scheme://host[:port]`, default port left out) for the redacted spec's
    `url_origin` (Task 4). Additive.
  - Docstrings on the public functions; the plan's `_segments` helper is inlined.
- `tests/scanner/test_urls.py`: the plan's 5 tests (lines wrapped to 100 characters, one extra
  `scheme` verdict assertion) plus the two above and `test_url_errors_carry_the_code_only`: 8
  tests (plan: 5).

## Task 3 — Migrations 030–031

- `dps/migrations/030_scans.sql`: the plan's DDL, except the sequence grant is the M2 `009` idiom (a
  `DO` block over `pg_get_serial_sequence(…)`, `GRANT USAGE, SELECT`) instead of naming
  `dps_scan_*_id_seq` literally. Why: identity sequence names are generated by PostgreSQL; the
  `009` form cannot drift from them. Same privileges (plus `SELECT`, as `009` grants).
- `dps/migrations/031_tenant_hosts.sql`: as planned, with a header comment (GLOBAL table, empty list
  semantics).

## Task 4 — Scan specification, records and API models

- `dps/jobs_models.py`: `ScanScope`, `ScanAuth`, `FillSpec`, `CaptureSpec`, `ScanSpec`, `PATH_GLOB`,
  `SECRET_REF` and `JobSecret.scan_start_url` as planned (M2 shipped no placeholder `ScanSpec`).
  Every scan model is `extra="forbid"` **and** `hide_input_in_errors=True` (the M2 convention: a
  start URL can carry personal data in its query, and pydantic's default error text would quote
  it). `FillSpec` checks the locale against `SUPPORTED_LOCALES` exactly (no `normalise_locale`
  mapping, so `fr_FR` is refused rather than silently becoming `en_US`). `ScanAuth` refuses both
  sources together and a `..` segment.
- `dps/layers/scanner/models.py`: the planned models, plus:
  - **Page data never reaches a `repr`.** Every facts field that can hold page data (labels,
    placeholders, titles, aria labels, name/id attributes, selectors, options, pre-filled values,
    rendered text, label hints, hrefs, form actions, frame paths, the page URL and title) is
    `Field(repr=False)`, and `ValidatedScan.__repr__` shows the origin and limits only (its
    `start_url` keeps the raw query). A traceback or a stray `repr()` therefore cannot carry page
    data. Test `test_page_facts_never_show_page_data_in_repr`.
  - `validate_scan` treats any `@` in the netloc as userinfo (the plan's `username is not None`
    misses `http://:pw@host/`), resolves and range-checks `max_depth` (0..5) and `max_pages`
    (1..`scan_max_pages`) for programmatically built specs too, and adds one code, `auth_invalid`
    (both storage-state sources, or a `..` ref, in a spec built around the model's validator).
    `hosts` is normalised (trimmed, lower-cased) into `ValidatedScan.hosts`.
  - `redact_scan_spec` also records the resolved `scope.max_pages` / `scope.max_depth` and two
    more value-free flags, `consistency.caller_key` / `caller_seed` (the run spec's `redact_spec`
    records the same facts), beside the planned `key_wrapped`.
  - `PersonaPreviewRequest` is `extra="forbid"` and checks its locale like `FillSpec`.
  - `ValidationMessage.text` is capped at 200 characters by the model (the plan's comment).
- Contract §3.3 (`JobSecret.scan_start_url`) and §9 (the M4 additions to `ScanSpec`, the accept-time
  codes incl. `auth_invalid`, and what the stored spec keeps) updated in this commit.
- **Not done here (Task 16):** `auth.storage_state_ref` is only validated for form. It must be
  resolved with the tenant-scoped resolver that SEC-2 introduces at integration
  (`DPS_SECRET_DIR/<tenant_id>/<ref>/`); nothing in M4 may resolve a ref in the global namespace.
- `tests/scanner/test_models.py`: the plan's 10 cases (parametrised codes extended with
  password-only userinfo, a non-http scheme and a start path outside `allow`) plus programmatic
  re-checks, inline auth where allowed, resolved limits, no-echo validation errors, the
  `JobSecret` field, the facts `repr` test and the preview request bounds: 20 tests (plan: 10).

## Task 5 — Scan store

- `dps/layers/scanner/store.py`: the planned interface and SQL. Decisions:
  - **jsonb as Python objects.** `dps/db.py` registers a `json.dumps`/`json.loads` codec for
    `json`/`jsonb` on every pool and on the migration connection, so (as the plan instructs in that
    case) jsonb parameters are passed as Python objects, not pre-encoded text; the `::jsonb` casts
    stay.
  - `add_request_counts` merges rows with the same key in Python before the multi-row upsert:
    PostgreSQL refuses `ON CONFLICT DO UPDATE` that touches one row twice in a statement
    ("cannot affect row a second time"), which a guard batch with two identical keys would hit.
  - `replace_fields` and `reset_scan` run in one transaction (a savepoint when the caller already
    holds one); `replace_fields` refuses a record whose `page_no` differs from the argument
    (`ValueError`, value-free).
  - `summary_counts` also returns `pages_discovered` and `pages_queued` (two `count(*)`s; the API's
    `ScanSummary` needs both); null aggregates come back as `{}`, every count as `int`.
  - `list_pages`/`list_events` clamp `limit` to 1..1000; `list_requests` orders by page (log-wide
    rows first), method, decision, reason, host.
  - `export_artefacts` takes the newest artefact per kind (`DISTINCT ON`) and returns only the kinds
    present.
  - `insert_evidence` refuses a pack whose `tenant_id`/`job_id` differ from the arguments and stores
    `pack.pack_version`. (M2's `save_evidence` also exists; Task 16 may use either.)
  - `browser_workers_online` passes the window as `float` (`make_interval(secs => …)` takes
    double precision).
- `tests/scanner/test_store.py`: the plan's 7 tests plus the schema-name check, keyset paging of
    pages, the RLS case on `get_page`, the in-batch duplicate key, `non_get_allowed` counting an
    allowed POST (and not a HEAD), and export artefacts + evidence insertion: 11 tests (plan: 7).
