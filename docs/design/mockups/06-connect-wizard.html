  • 1,948,210 rows in CRM.CUSTOMERS are updated by CUSTOMER_ID: 10 columns each, in batches of 5,000 per partition across 8 partitions.
  • Applications and reports that read CRM.CUSTOMERS see protected values as each batch commits.
  • The originals can be restored only with the key returned when the job finishes. The key is shown once and DPS keeps no copy; if it is lost, the original values cannot be recovered.
  • Synthetic values have no path back. After the write, the original values in these 10 columns are gone.
  • PIN_CODE and RISK_SCORE use one-way methods (generalize, bucket). Those two columns cannot be restored, even with the key.
  • If a partition fails it resumes from its last committed batch. No row is left half-written.
  • CRM.CUSTOMERS grows from 4,102,377 to 6,050,587 rows. Existing rows are not changed.
  • New rows get CUSTOMER_ID = original + 90,000,000 (90,000,001 to 131,882,907). The evidence pack records the range.
  • Reports and jobs that read CRM.CUSTOMERS will count the new rows until you remove them.
  • The key that reverses the new rows is returned once when the job finishes. DPS keeps no copy.
  • The new rows are synthetic and have no path back to real customers.
